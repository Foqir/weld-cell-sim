# weld-cell-sim: цифровой двойник роботизированной ячейки дуговой сварки

ROS 2 Jazzy + Gazebo Harmonic + MoveIt 2 + ros2_control в одном Docker-образе `weld-cell-sim`.
Робот: **HD Hyundai Robotics HDR20-17** (20 кг, вылет 1742 мм, ближайший к коботу HDC25-18: 25 кг / 1880 мм)
по официальным пакетам производителя: `hdr_description`, `hdr_ros2_driver` (MoveIt-конфиги),
`hdr_simulation_gz` (github.com/hyundai-robotics, ветка `jazzy`).
Проект полностью независим от `px4-vtol-sim` (БПЛА): свой образ, свой контейнер, свои бэкапы.

## Запуск

| Файл | Что делает |
|---|---|
| `fetch_deps.bat` | Один раз перед сборкой: клонирует официальные пакеты HD Hyundai Robotics на зафиксированных коммитах (`hdr.repos`) |
| `demo.bat` | Ячейка + сразу программа сварки всех швов (окна Gazebo и RViz) |
| `start.bat` | Только ячейка, в консоли контейнера: `weld_demo.sh` |
| `shell.bat` | Второй терминал в работающем контейнере |
| `build.bat` | Пересборка образа по этапам (с бэкапом слоёв в `backup\buildcache`) |
| `restore.bat` | Восстановить готовый образ из `backup\weld-cell-sim.tar` без интернета |

Параметры `start.bat` / `demo.bat`:
```
start.bat [hdr20_17|hh020|hdr35_20] [--demo] [--headless] [--no-rviz] [--offset DX DY DYAW]
```
`--offset 0.002 0.001 0.5` смещает **реальную** деталь в оснастке (м, м, град) относительно номинала,
по которому написана программа: для исследования влияния допусков на положение шва.

Внутри контейнера:
```
weld_demo.sh                                   # все швы
weld_demo.sh -p seams:="['tube_ring']"         # один шов
weld_demo.sh -p speed_factor:=2.0 -p cycles:=3 # быстрее, несколько циклов
```

## Что моделируется

* **Ячейка** (`config/cell.yaml`): робот на полу, сварочный стол, деталь в оснастке (прижимы, фиксаторы),
  источник тока, барабан проволоки, станция очистки горелки, ограждение. Из этого же файла
  генерируются мир Gazebo и сцена столкновений MoveIt.
* **Деталь**: кронштейн/усилитель из листа 4 мм: основание, вертикальное ребро, втулка-труба.
* **Горелка** MIG/MAG с изогнутой шейкой 45°, TCP = конец проволоки (вылет 15 мм).
* **Программа сварки** (`config/weld_program.yaml`): 3 угловых шва a3:
  `rib_left`, `rib_right` (прямые, 240 мм) и `tube_ring` (кольцевой вокруг трубы, 370°).
  Для каждого шва: ток, напряжение, скорость, подача проволоки, рабочий угол и угол наклона горелки.
* **Цикл шва**: PTP-переезд (OMPL, с обходом препятствий) → линейный подход → поджиг дуги по сигналу
  «в позиции» → сварка с постоянной скоростью TCP (IK в каждой точке через 1 мм) → заварка кратера →
  линейный отход.
* **Визуализация**: номинальные швы (зелёные), валик с цветом «остывания» (белый → оранжевый → серый),
  дуга, строка состояния над деталью (RViz); валик и дуга также рисуются в окне Gazebo.

## Результаты (логи для статьи)

Каждый прогон пишет папку `shared\logs\weld_<время>\`:
* `summary.json`: по каждому шву длина, скорость (заданная и измеренная), погонная энергия
  Q = η·U·I/v, время горения дуги, расход проволоки, отклонение TCP от траектории (среднее, RMS, максимум);
  по циклу общее время и доля горения дуги.
* `tcp_log.csv`: TCP и суставы с шагом 20 мс.
* `tcp_path_top.png`, `tcp_deviation.png`, `tcp_speed.png`, `joints.png`: графики.

Эталонный прогон (HDR20-17, номинальная деталь): цикл ≈ 150 с, горение дуги ≈ 78 с (≈ 51 %),
отклонение TCP при горящей дуге RMS ≈ 0.02–0.05 мм, максимум < 0.5 мм, скорость 9.9 мм/с при заданных 10 мм/с.

## Структура

```
Dockerfile, build.ps1          этапы deps -> hdr-build -> final, бэкапы в backup\
ros2_ws/src/hdr_*              официальные пакеты HD Hyundai Robotics (без изменений)
ros2_ws/src/weld_cell/         пакет ячейки
  config/  cell.yaml, weld_program.yaml, controllers.yaml, kinematics.yaml, initial_positions.yaml
  urdf/    weld_cell.urdf.xacro (робот + горелка + gz_ros2_control), welding_torch.xacro
  srdf/    группа MoveIt "welder" (base_link -> torch_tcp)
  launch/  weld_cell.launch.py
  scripts/ weld_program.py (задание сварки), plot_weld_log.py
  weld_cell/ geometry.py (ячейка, швы, мир Gazebo), report.py (метрики, графики)
scripts/  start_all.sh, weld_demo.sh, env.sh
tools/    check_reach.py (офлайн-проверка достижимости без ROS)
```

## Известные особенности

* Пока открыто окно Gazebo через WSLg, на хосте может перестать работать клавиша «P»
  (было в проекте БПЛА); после остановки контейнера проходит. Альтернатива: `--headless`.
* Переезды MoveIt в конфигурации Hyundai ограничены 10 % скорости (их рекомендация: не больше 20 %).
* Модели кобота HDC25-18 в открытом доступе нет (серия вышла в июле 2026); используется HDR20-17.
